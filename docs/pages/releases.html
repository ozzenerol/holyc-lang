Releases

What changed in each version of this fork of hcc. Binaries for Linux x86_64, Linux arm64 and macOS are attached to each release on GitHub.

v0.4.0 (2026-10-09)

Every known issue from v0.3.0 is fixed: two wrong-code bugs, standard-library fixes for threads, trees, processes, sockets and JSON, and diagnostics that point at the right place. The old x86 backend is gone. Every fix has a regression test that runs both compiled and in the JIT, on Linux x86_64, Linux arm64 and macOS.

Changes you may notice

  • --use-legacy-x86 is removed: the old AST-based x86_64 code generator had several wrong-code bugs, and the flag is now an error.
  • System and Sh return the command's exit code (0 to 255), or -1 if it was killed by a signal or couldn't run; they used to return the raw wait status (System("exit 3") was 768). System(NULL) returns -1.
  • NetSetSocketNoDelay returns TRUE on success; it returned the opposite.
  • A definition keeps its prototype's default arguments; giving the same parameter a different default in both is an error.
  • JsonParse honours JSON_STRNUM_FLAG: numbers are kept as their source text.
  • A function pointer can be called through *: (*fp)(), as in C.
  • RBTree is 8 bytes larger (each tree has its own sentinel node).

Fixes

  • Classes of any size from 1 to 16 bytes are passed and returned by value correctly. Odd sizes (3, 5 to 7, 9 to 15 bytes) overwrote neighbouring memory on x86_64 and didn't compile on arm64.
  • A class item in a local initialiser list (L l = {1, p0, 4};) is copied; it was garbage.
  • ThreadPoolRelease no longer hangs; queued jobs still run before it returns.
  • RBTreeRelease frees the tree and calls the key and value free functions; replacing a value frees the old one. Trees used on different threads no longer corrupt each other.
  • An asm {} block no longer breaks the parsing of the code after it, depending on where it sat in the file.
  • The C transpiler writes array members with their element count and indexing as a[i].
  • Cross-compiling for macOS from Linux (--target=*-apple-darwin) assembles.
  • Diagnostics at the right place: a wrong argument type at the argument, a class initialiser warning at its item, a missing name after a comma at the bad token. A class assigned to an integer is reported once, the underline under strings includes the quotes, and the U0 return warning prints the expression as written.

Still open: see Known issues.

v0.3.0 (2026-10-09)

A wrong-code fix in the optimiser, library functions you can redefine, new warnings for mistakes hcc used to accept silently, and three fewer ways to crash the compiler. Every fix has a regression test that runs both compiled and in the JIT.

Changes you may notice

  • Conflicting declarations of a function are an error ("conflicting types"), also against the standard library's prototypes. Programs that declared a library function with a different signature used to compile and now don't.
  • New warnings: a number with a leading zero (0644 is decimal 644, not octal), a pointer converted to one of a different scalar type (I64 *q = &f with F64 f), and a pointer difference stored back into a pointer (q -= q). -Werror makes them errors.
  • Redefining a library function (your own Now()) works in compiled programs too; it used to fail to link. Library functions are now weak symbols in libtos.

Fixes

  • Copying a pointer and then reassigning the original no longer changes the copy (I64 *z = v; v = &x; made *z read x, or crash once v was NULL).
  • A U0 * compares with a function pointer using == and !=.
  • No more crashes on I64 a[; or on * applied to something that isn't a pointer (1 +* 2); both are normal errors.
  • A stray ; at the top level (I64 x = 1;;) is accepted instead of swallowing the next declaration; in the REPL it also no longer breaks later results.
  • The C transpiler writes classes and unions after the types they contain and turns F32 into float.
  • The standard library's own prototypes now match their definitions (ListDeque, ListPop, StrMapSet, FzFGetScore).
  • The LSP tests take seconds instead of over a minute.

Still open: see Known issues.

v0.2.0 (2026-10-09)

Networking and parser fixes: sockets now work the same on Linux and macOS, and five more compiler bugs are gone, each with a regression test.

Changes you may notice

  • NetAccept returns an I32: the new socket, or -1 on failure (it used to return a value you couldn't check).
  • \x in strings and character constants takes at most two hex digits, as in C, so "\x01b" is the bytes 1 and 'b', the same in AOT and the JIT.
  • sizeof of a string literal always counts its terminating NUL (sizeof("\xa3\xFF") is 3).

Fixes

  • Socket address layouts and constants follow the platform: sockaddr layouts, the Linux TCP_* options, AI_NUMERICSERV; IPPROTO_* are exported.
  • The arm64 JIT sign-extends I32 locals at large frame offsets (negative values read back as large positive ones).
  • A modulo or division by a variable inside an array subscript no longer crashes hcc; division or modulo by a constant 0 is reported as an error.
  • Two bad statements in a row no longer crash hcc; error recovery skips a stray } at the top level.
  • Brace elision works for class-typed and array fields of initialiser lists (Q q = {1, 2, 3}; where the last field is a class).
  • String escapes are emitted so the assembler can't misread them, so AOT and JIT strings are byte-for-byte the same.
  • Character constants accept every escape strings do: '\b' is 8, not 92.
  • make build works, and make no longer copies build.sh over the build directory.
  • The test suite runs on macOS, which has no timeout command.

Still open: see Known issues.

v0.1.0 (2026-10-09)

The first release of this fork, which is developed independently of Jamesbarford/holyc-lang (it continues from upstream v0.0.15-beta). It is mostly about correctness: 120 fixes, each with a regression test that runs both compiled and in the JIT.

Highlights

  • Wrong code fixed: loads through pointer arrays, global initialisers laid out at their field offsets and zero-filled, int/float conversions on return, assignment and intrinsic classes, return f(); in U0 functions no longer dropped, &&/||/! on floats and pointers, comparisons with the pointer on the right, register clobbering in indexed loads on arm64 and x86_64, stack-passed parameters.
  • No more compiler crashes or hangs on bad or truncated input: end of file anywhere, errors inside class bodies, initialisers and directives, runaway compound assignments.
  • Language: nested #if handled properly, #undef applied in order, #define line continuation and float typing, function-pointer arrays and file-scope function pointers, nested/union/string initialisers, calling a function without parentheses anywhere in an expression, C precedence for prefix operators.
  • Diagnostics at the right place: macro uses, directives, tabs and non-ASCII text, argument counts; clear messages for malformed numbers and unknown characters.
  • Standard library: JSON \u escapes, top-level values and round-tripping; IntSet, CatPrint, FileRead, RBTreeDelete and %d of the smallest I64 fixed.
  • Building and testing: ./build.sh builds into a local prefix and runs the suites; docker/test.sh tests x86_64 and arm64 Linux; documentation with checked examples, published at ozzenerol.github.io/holyc-lang.

Still open: see Known issues.
