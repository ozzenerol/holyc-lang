Known issues

Bugs found while writing and testing these docs and while testing the compiler, each with a way to reproduce it and a workaround. The other pages avoid them, so every example there works as shown.

Compiler

ProblemReproduceWorkaround
No brace elision for class-typed fields class L { I64 t; P a; I64 z; }; L l = {1, 2, 3}; warns instead of filling a's fields Brace the inner class: {1, {2, 3}, 4}
Assigning a U0 * to a function pointer warns U0 *v = &F; I64 (*fp)(I64 x) = v;: "'U0 *' is not assignable to type '<fn> I64'" The assignment still works; ignore the warning
No line continuation in #define A #define ending in \ gives confusing errors placed at an earlier line Keep each #define on one line
Skipped #if blocks still report some errors #if 0 / I64 x = 0b12; / #endif reports the malformed number; C ignores skipped code Keep code inside #if 0 lexically valid

Diagnostics

ProblemReproduceWorkaround
A wrong argument count is underlined at the wrong place U0 Main() { I64 x = One(1); I64 y = Two(1); }: the error for Two underlines Main() Read the function name in the message
Warnings for compound assignments and some pointer/array mismatches point at the nearest = y = y + q; arr = arr + 1;: the warning for the second statement is placed on the first Read the types in the message
The "perhaps a missing ;" hint can point at the wrong line U0 Main() { / I64 x = 2 3;: the hint points at U0 Main() { Ignore the hint when that line can't take a ;
Carets are misplaced after non-ASCII text I64 x = 1 €é;: the caret for é is two columns too far right (columns count bytes) Use the reported column
Array types show their size in bytes A diagnostic about I64 arr[2] calls it I64[16] Divide by the element size

JIT and code generation

ProblemReproduceWorkaround
The legacy x86 backend lays out global class initialisers without field offsets Only with --use-legacy-x86: class P { I32 a; I64 b; }; P g = {1, 2}; gives a wrong g.b Use the default backend

Standard library

ProblemReproduceWorkaround
IntSet doesn't store anything IntSetAdd(s, 5); then IntSetHas(s, 5) is 0 and IntSetSize(s) is 0; unions and differences are empty Use an IntMap with dummy values
%d of the smallest I64 prints garbage "%d\n", 0x8000000000000000; prints punctuation instead of -9223372036854775808 Special-case that value
NetAccept returns Bool, and NetCreateServer returns 0 on some failures A socket number over 255 from NetAccept is truncated; 0 from NetCreateServer looks like a valid socket Call accept directly, and treat <= 0 from NetCreateServer as failure
Unix domain sockets don't work on Linux sockaddr_un has the BSD layout (a leading length byte), so NetCreateUnixServerSocket fails and returns 0; a path over 104 bytes also overflows it Use TCP on 127.0.0.1

Reporting

Please report bugs on GitHub. A minimal .HC file that reproduces the problem helps the most.
