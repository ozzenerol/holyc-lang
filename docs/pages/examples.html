Example projects

Six complete programs in docs/examples/, each with the exact output it should produce. They double as tests: docs/examples/run.sh builds every project, runs it both compiled and in the JIT, and compares the output with its expected.txt.

docs/examples/run.sh          # all projects
docs/examples/run.sh life     # just one

Word frequency

Reads a text file and prints its most common words. It shows reading a file, scanning characters, counting with a StrMap, ranking with PtrVecSort, and reading command-line arguments.

cd docs/examples/wordfreq
hcc main.HC -o wordfreq && ./wordfreq sample.txt

Bank

Accounts with monthly interest and a transaction log. A savings account inherits from Account and swaps in its own interest function through a function pointer. Errors are exceptions, and a failed transfer rolls itself back. Money is kept in integer cents, so no rounding errors creep in.

cd docs/examples/bank
hcc main.HC -o bank && ./bank

Game of Life

Conway's Game of Life on a small board that wraps at the edges, with a glider and a blinker. It shows 2D arrays, nested loops, % for wrap-around and MemCpy on whole arrays.

cd docs/examples/life
hcc main.HC -o life && ./life

Echo server

A multithreaded TCP echo server and its test clients in one program. The server binds to port 0 so the kernel picks a free port, reads it back with getsockname, and gives every connection its own thread. Four client threads connect at the same time and send their message in 5-byte pieces: TCP is a byte stream, so both sides loop until every byte is sent or received. A mutex guards the server's counters.

cd docs/examples/echo
hcc main.HC -o echo && ./echo

HTTP server

A small HTTP/1.0 server with a thread per connection and three routes: a greeting, an /add route that reads two numbers from the query string, and 404/405 replies for everything else. The client side sends five requests at once, then parses each status line and body with strchr, strstr and Atoi.

cd docs/examples/http
hcc main.HC -o http && ./http

Key-value store

A server speaking a line protocol (SET, GET, INCR, DEL, COUNT), with every client on its own thread and all of them sharing one StrMap behind a mutex. Four clients run at once and each bumps the same counter 250 times; the final count of 1000 shows no update was lost. Remove the lock and the threads corrupt the map. It also shows splitting a TCP stream into lines and letting the map free its keys and values.

cd docs/examples/kvstore
hcc main.HC -o kvstore && ./kvstore

More examples in the repository

The compiler's own test suite, src/tests/, has more than 60 small programs, one per feature: threads, JSON, SQLite, coroutines, fuzzy matching and more. The standard library in src/holyc-lib/ is all HolyC too, and worth reading.
