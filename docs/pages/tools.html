Tools

One binary, hcc, does everything: compiling, JIT, REPL, language server, transpiler and debugging output.

Compiling

hcc main.HC -o app          # build ./app
hcc main.HC                 # build ./a.out
hcc -S main.HC -o main.s    # assembly only
hcc -S -o- main.HC          # assembly to stdout
hcc -c main.HC -o main.o    # object file, to link later
hcc main.HC util.o -o app   # link object files in
hcc -DDEBUG main.HC         # define a macro (no value)
hcc -Werror main.HC         # treat warnings as errors

Link C libraries with -clibs, or record them in the source with #link:

hcc game.HC -clibs="-lSDL2 -lm" -o game

hcc hands the generated assembly to the system C compiler through a temporary file in $TMPDIR (/tmp if unset), one per compile and removed afterwards, so several compiles can run at once.

The JIT

hcc -jit file.HC assembles machine code into memory with hcc's built-in assembler and runs it. No C compiler, linker or files are involved, so it starts fast. Arguments after the file are passed to the program. A file with no Main and no code at file scope has nothing to run: -jit says so and exits with 1. Use #ifjit / #ifaot for code that should differ between the two modes.

hcc -jit server.HC 8080

The REPL

hcc -repl

HolyC runs as you type it, TempleOS style. Functions, classes, globals and #defines accumulate across the session, and the value of a trailing expression is echoed:

> I64 Sq(I64 x) { return x * x; }
> Sq(7);
49
> "hello %d\n", Sq(3);
hello 9
  • Line editing, history (~/.hcc_repl_history) and tab completion are built in.
  • ~/.hcc_rc.HC is included at start-up. Put #define HCC_NO_REPL_HELLO in it to hide the welcome message.
  • Uf("Name"); disassembles a function. ReplDel("name"); forgets a definition so you can redefine it.
  • @ ls -la runs a shell command. It goes through system(), so @ cd doesn't change the REPL's directory.
  • Allocations are tracked, so leaks and bad frees are reported.

Editor support

hcc -lsp is a language server: errors and warnings as you type, hover, completion (including after . and ->), go to definition, find references, highlighting and rename. It works with any editor that speaks LSP.

Neovim

vim.filetype.add({ extension = { HH = "holyc", HC = "holyc", hc = "holyc" } })

vim.api.nvim_create_autocmd("FileType", {
  pattern = "holyc",
  callback = function(ev)
    vim.lsp.start({
      name = "hcc",
      cmd = { "hcc", "-lsp" },
      root_dir = vim.fs.root(ev.buf, { ".git" })
                 or vim.fs.dirname(vim.api.nvim_buf_get_name(ev.buf)),
    })
  end,
})

Other editors

Point your editor's generic LSP client at the command hcc -lsp for .HC and .HH files. If hcc isn't installed, add --install-dir=/path/to/build/prefix so it can find the library header. Set HCC_LSP_LOG=1 in the server's environment to log its traffic to stderr. Syntax highlighting for Vim is in src/syntax-highlighting/hc.vim.

Libraries

Build your own HolyC library and install it next to the standard one:

hcc -lib mylib --install-dir=$HOME/.local mylib.HC

This produces libmylib.a and a shared library in $HOME/.local/lib. Mark the functions and globals it exports public. To use the library, declare its functions, and its globals with extern (extern I64 count;, extern I64 (*hook)(I64);), usually in a .HH header you #include, and add #link <mylib>.

The transpiler

hcc -transpile main.HC > main.c

This prints a C version of the program. It's experimental and frozen: it supports the language as of v0.18 and gets no new features, so language and library features added later may not translate. Comments are dropped, and some programs need fixing by hand. Globals are written with their initialisers; code at file scope (initialisers that aren't constant, statements) goes into __hcc_init(), which main calls first. The program is checked by the compiler first: its warnings and errors are printed as for a compile, and an error stops the transpile with exit status 1, so a wrong program gives no C. The program is parsed twice, once for the check and once for the C.

Looking under the hood

hcc -tokens main.HC                 # what the lexer sees
hcc -ast main.HC                    # the parsed program
hcc --dump-ir main.HC               # the SSA intermediate representation
hcc -S -o- main.HC                  # the generated assembly
hcc -cfg main.HC && dot -Tpng main.dot -o main.png
