Known issues

Bugs found while writing and testing these docs (hcc v0.0.15-beta), each with a way to reproduce it and a workaround. The other pages avoid them, so every example there works as shown.

Compiler

ProblemReproduceWorkaround
A function pointer with named parameters doesn't parse outside a function I64 (*g)(I64 a, I64 b) = &Add; at file scope: "Identifier expected" Declare it inside a function, or assign it in Main
|| rejects a pointer next to a call returning Bool if (p || T()) where T returns Bool Compare the pointer: p != NULL || T()
Extra tokens after an #if condition are ignored #if 0 1 is the same as #if 0, with no error Check the #if lines
Hex letters after a decimal number are ignored I64 x = 123abc; compiles, and x is 123 None needed; just don't write it
A postfix cast inside a #define crashes hcc #define X (5(U64) % 3), then use X Cast outside the macro, or use a variable
An assignment used as a value has type I64, not the class (c = Mk()).date where c is a CDate: "Expected as class" Assign first, then read: c = Mk(); c.date

JIT and code generation

ProblemReproduceWorkaround
Reading a whole I64 class through a pointer gives the pointer CDate *pp = a; CDate d = pp[2]; (also *pp) Copy the fields: d.date = pp[2].date; d.time = pp[2].time;
Default arguments are ignored when calling through a class field function pointer class C { I64 (*f)(I64 a, I64 b=10); }; c.f(1) passes garbage for b Pass every argument

Standard library

ProblemReproduceWorkaround
CatPrint returns a new string and never frees the one you pass s = CatPrint(s, "%d", i); in a loop leaks every old s Keep the old pointer and Free it after the call

Reporting

Please report bugs on GitHub. A minimal .HC file that reproduces the problem helps the most.
